1. INTRODUCTION                                       *org-columnview-introduction*

A port of the Emacs Org column view (|org-colview|) for Neovim. The column
view overlays a tabular structure over the headlines of an org buffer, and
renders the agenda as a table of columns. The values can be edited in place,
and the layout of the columns can be changed and is written back to the
buffer, like in Emacs.

==============================================================================
2. REQUIREMENTS                                       *org-columnview-requirements*

nvim-orgmode is required for the org file, headline and agenda handling:

  https://github.com/nvim-orgmode/orgmode

The plugin works with the `master` branch of nvim-orgmode, no patches are
needed. It uses internal modules of nvim-orgmode, which are not a stable
public API, so changes there can break the plugin.

==============================================================================
3. SETUP                                                     *org-columnview-setup*

The plugin has to be set up after nvim-orgmode, because the setup call of
nvim-orgmode creates the instance that the plugin registers itself on: >lua

    require('orgmode').setup()
    require('org-columnview').setup()
<
With lazy.nvim: >lua

    {
      'nvim-orgmode/orgmode',
      dependencies = { 'nvim-orgmode/org-columnview.nvim' },
      config = function()
        require('orgmode').setup()
        require('org-columnview').setup()
      end,
    }
<

4. MAPPINGS                                               *org-columnview-mappings*

Entry points: >

    org_columns            <prefix>xc    Toggle the column view in an org
                                          buffer. It shows the subtree of the
                                          headline that owns the COLUMNS
                                          property, the subtree under the
                                          cursor when no entry owns it, or
                                          the whole file when the cursor is
                                          before the first headline. A count
                                          prefix (`1<prefix>xc`) always shows
                                          the whole file, like Emacs' `C-u
                                          C-c C-x C-c`.
    org_columns_insert_dblock
                           <prefix>xx    Insert a columnview dynamic block.
    org_columns_update_dblock
                           <prefix>xu    Update the block at the cursor. With a
                                         count prefix, update every block in
                                         the buffer.
    org_agenda_columns     <prefix>ac    Open the agenda as a column view.
<
The prefix is the one of nvim-orgmode (|orgmode-mappings|), `<Leader>o` by
default, so the defaults are `<Leader>oxc` and `<Leader>oac`.

In the agenda, `<prefix>xc` opens the column view of the agenda as well, like
in Emacs, where the same key opens the view of the current buffer. The column
view is also an entry of the agenda prompt (`<prefix>oa`), under the key `c`.

While the column view is open, these buffer local mappings are available: >

    h / l         Previous / next column
    k / j         Previous / next row
    1 ... 9, 0    Select the 1st..10th allowed value
    n / p         Next / previous allowed value
    e             Edit the value at point
    C-c C-c       Toggle the checkbox at point, or quit the column view
    q             Quit the column view
    v             View the full value of the current cell
    a             Edit the allowed values of the current column
    < / >         Narrow / widen the current column (a count prefix
                  adjusts by N)
    S-M-Right     Insert a column
    S-M-Left      Delete a column
    M-Left        Move the current column left
    M-Right       Move the current column right
    M-Up          Move the current row up
    M-Down        Move the current row down
    s             Edit the current column attributes
    r             Refresh the view from the file
    c / o         Switch between content and overview
    C-c C-o       Open the link at point
    C-c C-t       Change the TODO state
    g?            Show the help
<
The cell under the cursor is highlighted. Moving the cursor to another
headline moves the highlighted cell with it.

5. COLUMN FORMAT                                           *org-columnview-format*

A column format is a space separated list of column specifications: >

    %[width]PROPERTY[(Title)][{summary}]
<
    width              Column width in characters (optional)
    PROPERTY           Any property name, or one of the special columns
    (Title)            Display title (optional, defaults to the property)
    {summary}          Summary operator for entries with children, optionally
                       followed by `;FMT` (optional)

Allowed values are read from the PROPERTY_ALL property, matching Emacs. The
property is looked up on the entry and its ancestors, and finally file-wide
via `#+PROPERTY: PROPERTY_ALL ...` or `#+PROPERTY_ALL: ...`.

Legacy formats may still contain a second brace group with inline values or
a {NAME_ALL} reference. The plugin reads it for backwards compatibility, but
writes the values to PROPERTY_ALL and drops the brace on the next format
change. Inline allowed values are not portable to Emacs.

Add `:ETC` to a PROPERTY_ALL list to mark the values as suggestions rather
than a closed set. Cycling skips `:ETC`, while `e` accepts arbitrary input.

Editing the allowed values with `a` stores the string exactly as typed; both
comma-separated and whitespace-separated lists are parsed for cycling.

Special column names: `ITEM`, `CLOCKSUM`, `CLOCKSUM_T`, `AGE`, `TAGS`,
`ALLTAGS`, `TODO`, `PRIORITY`, `CATEGORY`, `SCHEDULED`, `DEADLINE`, `CLOSED`,
`TIMESTAMP`, `TIMESTAMP_IA`, `FILE` and `BLOCKED`.

Summary types: `+` (sum), `$` (currency sum), `:` (duration sum), `:min`,
`:max`, `:mean` (duration extremes and mean), `min`, `max`, `mean`
(numeric), `X`, `X/`, `X%` (checkboxes), `@min`, `@max`, `@mean` (age
extremes and mean) and `est+` (low/high estimates).

An optional `;FMT` after `+`, `min`, `max` or `mean` formats the summary
and the displayed cell values, e.g. `{+;%.2f}` or `{min;%.1f}`.

`X/` and `X%` count `[n/n]` and `[100%]` cookies as done. Age summaries
(`@min`, `@max`, `@mean`) accept Org timestamps or duration values.

With `write_summaries = true`, opening or refreshing the view writes each
summary into the first column's property on the parent entry. Only existing
properties are updated; missing properties are not created.

The format is looked up in this order: a `COLUMNS` property on the headline
or one of its ancestors, the `#+COLUMNS:` keyword of the file, and finally
the `default_format` option.

Changing the column layout (attributes, width, insert, delete, move) is
written back to the buffer, like in Emacs: into the `:COLUMNS:` property of
the headline the view started at when it has one, otherwise into the first
`#+COLUMNS:` keyword (created before the first headline if missing). The
agenda column view keeps such edits in memory only.

5.1 DYNAMIC BLOCKS                                *org-columnview-dynamic-blocks*

`#+BEGIN: columnview` dynamic blocks export the view as a static Org table.
Place the cursor where the table should go and run
`:OrgColumnsInsertDblock`. Update the block at the cursor with
`:OrgColumnsUpdateDblock`, or every block in the buffer with
`:OrgColumnsUpdateAllDblocks`. The same actions are bound to `<prefix>xx`
(insert) and `<prefix>xu` (update; a count prefix updates all blocks). >

    #+BEGIN: columnview :id local :hlines 1
    |ITEM|OWNER|SCORE|
    |-|
    |Project||Σ=5|
    #+END:
<
Parameters: >

    :id                 local (default), global, <ID>, or file:<path>.
                        Selects the current COLUMNS-owner subtree, the whole
                        file, an entry with that :ID:, or a file.
    :format             Column format; overrides the normal COLUMNS format.
                        Quote it when it contains spaces:
                        :format "%10ITEM %10OWNER"
    :hlines             t or a number. t adds a horizontal line before every
                        row; N adds one before rows with level <= N.
                        Inserting a block uses 1.
    :indent             t indents the ITEM cell by two spaces per level.
    :match              Org agenda tag/property match expression.
    :maxlevel           Omit headlines below this outline level.
    :skip-empty-rows    t drops rows whose non-ITEM columns are all empty.
    :vlines             t adds Org column-group markers for vertical lines.
    :link               t links ITEM cells to their source headlines.
    :exclude-tags       Space-separated tags to exclude.
    :formatter          Lua function for custom output; pass it through
                        require('org-columnview').update_columnview_dblock(
                        { formatter = fn }).
<
`t` is the Org/Emacs boolean true value, not a placeholder: `:hlines t`
means "hline before every row". Boolean parameters accept `t`/`true`/`1` to
enable and `nil`/`false`/`f`/`0` to disable.

Parameter names are case-insensitive. Quoted values may contain spaces;
unquoted values end at the next `:parameter`.

The table inside the block is parsed through a Tree-sitter injection, so
nvim-orgmode's table formatting, cell navigation and table-aware highlighting
work inside `columnview` blocks. Completion suggests `#+BEGIN: columnview`,
the block parameters, and common parameter values.

6. CONFIGURATION                                     *org-columnview-configuration*

>lua
    require('org-columnview').setup({
      -- Column format used when no COLUMNS property or #+COLUMNS: keyword
      -- is found
      default_format = '%25ITEM %10Effort(Effort){:} %10CLOCKSUM %10CLOCKSUM_T %10Tags %10TODO',
      -- Column format used in the agenda when nothing else is defined
      default_format_for_agenda = nil,
      -- Column format that overrides everything in the agenda
      overriding_columns_format = nil,
      -- Called with the column title and the value to produce the text that
      -- is shown. Return nil to keep the original value.
      modify_value_for_display_function = nil,
      -- Custom summary operators. A definition is either a function
      -- (values, format) or a table { summarize = fn, collect = fn }.
      summary_types = {},
      -- Functions that return allowed values for a property, or nil.
      allowed_value_functions = {},
      -- Marker appended to truncated cells.
      ellipsis = '…',
      -- Values cycled by checkbox summary columns.
      checkbox_allowed_values = { '[ ]', '[X]' },
      -- Ignore trees tagged ARCHIVE.
      skip_archived_trees = true,
      -- Write computed summaries into existing parent properties.
      write_summaries = false,
      -- Prefix of the mappings, defaults to the prefix of nvim-orgmode
      prefix = nil,
      mappings = {
        org_columns = '<prefix>xc',
        org_agenda_columns = '<prefix>ac',
        column_view = {
          quit = 'q',
          -- ... see the mappings above
        },
      },
    })
<
A mapping that is configured for nvim-orgmode wins over the one of the
plugin.
